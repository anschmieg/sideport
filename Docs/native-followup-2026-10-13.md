# Native audit follow-up — 13 October 2026

The release blockers are resolved for alpha 0.3.1. Detached-process ownership passes adversarial tests, and the stricter service policy passes a controlled GUI positive/negative retest. The installed app and live tunnel were not replaced, restarted or reconfigured.

## Implemented corrections

- Every sandbox invocation runs in a distinct kernel audit session with a trusted cleanup custodian. Ownership survives double-fork and `setsid`. Completion, timeout, broker exit, controller/custodian crashes and concurrent-session isolation pass. Sandboxed code cannot create a new security session or launchd job, or signal trusted host processes; signaling its own sandbox children still works.
- Broker and Smithery execution supervisors now close admission permanently at shutdown, preventing delayed work from starting a helper after disconnect or provider stop.
- GitHub credentials are captured through the protected existing CLI in the login session and delivered through private pipes. Token values are excluded from job manifests. Source environments require valid restricted, hardened signatures on Sideport and nono; updates preserve this requirement. Synthetic tests cover both child-environment exposure and foreign reads of a protected host environment. Normal macOS security enforcement is assumed; these tests do not certify a machine with SIP disabled.
- Older GitHub CLIs that cannot use an explicit macOS certificate bundle get an on-demand, checksum-pinned official helper. The existing CLI remains the Keychain source. The proxy uses a session CA and an explicit certificate bundle, without registering a new trusted CA. Authenticated account lookup and an owned-repository HTTPS push dry-run pass; no remote writes were performed.
- Restored computer contracts include app launch/open/relaunch options, binary/file clipboard transfer, private named slots, image formats/regions/displays, saved screenshots and file-dialog handling. Disk transfers run through the file sandbox. These contracts have compilation and focused regression coverage; every option across every app is not certified.
- Text replacement uses Accessibility value editing when supported. Insertion binds the selected receiver and uses targeted text edits or Unicode, with conservative pacing. Whole-field replacement, accented text and emoji insertion passed on the user's custom Colemak CAW setup. This does not certify every keyboard shortcut under that layout.
- Drag endpoints are selected by opaque element IDs, then resolved against fresh native elements. The SDK's complete receipt is preserved. Native foreground drag-and-drop and refusal after a source-label change pass. Background delivery is optional for controls supporting it. Foreground gestures can interrupt the current UI; outcomes remain unverified until the caller observes the result.
- Screenshot-only requests no longer incorrectly require an Accessibility detection pass. Mutation wrappers preserve action outcomes rather than claiming unverified operations completed.
- Smithery parsing accepts current CLI output variants, checks existing connection membership, and rejects URL/path injection. Live Smithery verification is unavailable because the installed CLI itself returns 404 for its existing namespace. Sideport now reports that distinction without exposing manager credentials or changing authentication.

## Permission-prompt incident and controlled retest

Repeated GUI audits from separate temporary signed app copies generated overlapping macOS direct-screen-access warnings while the user was away. The user allowed those requests. That was an audit workflow failure: screen permission probes and repeatedly launched builds can themselves generate consent UI.

All audit processes were checked as stopped. No remote tunnel was created by the audits. macOS permission state was not reset, and the installed app's connection was preserved.

Permission polling now uses non-interactive preflights. Native requests occur only after computer-control approval, once per desktop session, with a three-second pause and up to twenty seconds of polling. The GUI harness requires explicit `--interactive`, uses one fixed private audit app path and an exclusive lock, and asks for missing native permissions only with `--request-permissions`. Unattended GUI loops are prohibited.

The user authorized one subsequent controlled check. Actual capture, replacement/insertion, clicking, native drag-and-drop and changed-selector refusal passed. A sandboxed probe then returned access to the fixture, failing the containment assertion. The old report did not identify which of its two probe routes returned access; no user windows or clipboard contents were used.

The follow-up policy denies Mach service lookup by default, retaining a narrow networking/logging/certificate allowlist and explicit GUI, recording, Keychain and launch-service denies. Headless compatibility checks pass with this policy. Service-resolution probes do not request recording or capture pixels. GUI reports now identify each positive/negative route. The user explicitly approved one final check of the corrected policy. Both unsandboxed positive controls accessed the synthetic fixture. The sandboxed screen probe aborted with exit 134 without obtaining access; the sandboxed Accessibility probe returned `available: false`. The capture, exact text replacement, Unicode insertion, clicking, selector-based native drag and changed-selector refusal checks all passed. The report is retained at `../../outputs/Sideport-GUI-audit.txt`. No further GUI run is needed for the version-only release bump.

## Validation and limits

The native runner has twenty groups. Strict Swift formatting and Python harness compilation pass. The protected signed audit package validates disconnected startup, scoped gateway tokens, sandbox files/clipboard/credentials, Keychain-service refusal and the tunnel's local interface. The full isolated integration suite passes with the strict service policy: complete file operations, immutable code, symlink/hard-link/controller refusal, Unix-socket isolation, adversarial process ownership, agents-dev forwarding, fresh npm runtime/package admission, GitHub authentication and tray/admin/force-quit cleanup.

Full computer-control approval permits access beyond the file sandbox. Network and shared writable development caches remain deliberate trust choices. Command review does not prove arbitrary scripts safe. Same-user malware outside the sandbox, privileged/kernel compromise, hard resource quotas and future dependency upgrades are outside the verified claim. This is an early alpha audit, not a formal security certification.

The environment-read protection follows Apple's [process-argument implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sysctl.c) and [restricted-signature flag handling](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_cs.c), and is validated with synthetic secrets. The 0.3.1 release bundle includes these corrections and uses the existing signing identity. Packaging does not replace the installed app or change its live connection. The older 0.3.0 ZIP predates these corrections.
